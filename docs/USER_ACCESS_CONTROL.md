# 用户、角色与权限管理

管理员登录后进入「系统 → 用户与权限」，默认打开角色管理。先创建角色并配置功能和设备，再在用户管理中添加账户、分配角色。角色标识由界面自动生成。用户功能权限是所有已分配角色与用户附加功能的并集；附加功能收在高级设置中。用户归属创建者当前登录的租户，登录时填写同一个租户。

功能按「日常使用、设备接入、运维管理、系统管理」分组，运维租户中另有「运维中心」分组，默认仅展开日常使用。每项功能选择「关闭、查看、管理」；智能助手的「问答」同时授权普通及流式问答。「管理」授予该功能全部操作，包括删除等；特殊授权可展开细项设置。已有自定义权限原样保留，只有明确选择级别时才替换该功能权限，不影响其他功能。

## 设备访问范围

角色可选择「无设备、指定设备、当前租户全部设备」。指定设备支持按名称或编号搜索、逐台勾选和「仅看已选」核对清单。角色范围变更立即影响继承该角色的用户，无须逐人调整。

界面新建用户默认「继承角色」：多个角色的设备范围取并集，任一已分配角色授予全部设备时继承全部设备；没有角色或角色未授权设备时无设备可见。用户编辑中仍可选择无设备、指定设备、全部设备作为单独范围；**单独范围替代角色范围，不与角色设备合并**。已有用户保持原范围，不自动切换为继承；历史空范围仍按无设备处理。内置管理员仍管理当前租户全部设备。

必须同时具有设备管理功能及有效设备范围才可读取设备数据。未开通设备管理时，设备选择器可补充查看权限，不增加编辑、删除或控制操作。主设备和子设备分别授权，不隐式扩大到关联设备。设备、告警、原始报文、分页总数、总览统计、实时提醒和 AI 工具使用同一有效范围；无权访问的详情、历史、控制和告警处置请求由后端拒绝。

## 账户与操作权限

用户名使用3至64位字母、数字、点、横线或下划线；密码至少10字节、最多72字节。密码仅保存 bcrypt 哈希，不提供查询明文密码的接口。需要修改密码时使用「重置密码」。内置环境管理员保留为维护入口，不在此页面编辑或删除。

菜单权限提供对应页面及必要关联数据的读取能力；新增、编辑、删除、发布、下载、设备控制等操作另行授权。勾选操作时同时勾选其所属菜单。界面隐藏没有权限的按钮，后端按实际路由再次校验。一个页面涉及多个接口时，权限列表可能提供多个操作，例如普通问答和流式问答。运行总览只统计授权设备。巡检、备份、接入配置、规则、摄像头及用户权限管理属于全租户任务或管理入口，需设备管理菜单、全部设备范围及对应菜单和操作权限；指定设备用户不开放这些全租户入口。受限用户的连接详情只展示自身设备数据，不展示共享接入网关配置及其他设备会话。

智能助手允许指定设备或无设备范围的用户使用，仍需智能助手菜单及普通问答/流式问答操作授权。每次 MCP 工具调用重新检查用户是否启用、登录版本和最新角色权限，并应用与页面一致的设备范围；拥有智能助手菜单不会自动获得告警、运行总览、知识库或规则草稿权限。总览工具只汇总授权设备，未授权的产品、协议、规则、摄像头和知识库统计不返回；知识库仍需知识库菜单和 Agent 绑定范围，规则草稿仍需规则菜单及生成操作权限。全租户报告和 Agent 管理继续要求全部设备范围。普通用户未配置 Harness 时拒绝问答，不回退到旧的全租户知识检索路径。

告警研判按角色决定知识范围：拥有知识库菜单的角色手动研判时检索「AI 告警研判」智能体的文档，结果单独保存，只对拥有知识库菜单的角色显示；其他角色和自动研判不检索知识库。完整规则见 [AI 工作流](AI_PLUGIN_HARNESS.md#告警研判的知识范围)。

登录、当前身份及事件接口返回 `accessVersion`，由有效权限、设备范围和登录版本生成。浏览器聊天缓存和后端模型会话都按此版本隔离，收紧权限后不续用先前的回答、工具记录或模型上下文。

「设备管理 → 添加设备」沿用“新增设备”操作权限，权限列表不单列向导接口；向导中同时新建设备模板还需设备模板的新增权限，新建共享监听还需「平台接入点」的新增权限。只授权部分设备的用户不能添加设备。「平台接入点」菜单在设备模板详情的“接入点”中使用；只有该菜单、没有设备模板菜单的用户仍从侧栏进入独立页面。已删除接口遗留在角色或用户上的旧权限项不再显示，重新保存后自动去除。

### 运维中心权限

运维中心（运维总览、指标中心、日志中心、仪表盘、监控告警）的数据是全平台数据，不按租户或设备范围隔离，只能在 `IOT_OPS_TENANTS` 列出的运维租户中授予；其他租户的权限列表不显示这些项，保存时拒绝，已存在的授权在请求时剔除。菜单权限用于查看；PromQL / LogQL 查询、导出、规则、保留与删除、仪表盘编辑、数据源、静默和通知配置需要单独的操作权限。完整清单见 [运维中心权限](OPS_CENTER.md#权限)。

## 权限变更与实时提醒

修改角色功能或设备范围后，后续 API 请求立即使用新配置；普通用户的事件轮询也会同步有效权限，重新进入窗口或刷新同样会更新菜单和按钮。修改用户、停用用户、重置密码使原登录令牌失效，用户需重新登录。删除后重新创建同名用户不会恢复旧登录。正在使用的角色不能删除；不能删除内置管理员或当前登录账户。

所有登录用户每3秒请求受认证的 `/api/v1/events`，管理员读取当前租户，普通用户每次按最新权限和设备范围过滤活动告警与状态。租户数据快照最多缓存 2 秒并在该租户用户间共享，权限与设备范围仍逐请求判断，不写入共享快照；内容未变化时返回 304。普通用户不签发浏览器 MQTT 凭据，不能调用 MQTT 压测令牌接口；管理员仍通过 MQTT 接收解析事件和规则界面联动，但活动告警弹窗不依赖浏览器访问独立的 MQTT 端口。HTTP 页面生成 MQTT 客户端标识不再要求 `crypto.randomUUID()`。

登录后的初次成功快照不弹出历史告警，后续新增或更新的活动告警触发提醒；短暂网络失败保留上次成功快照，MQTT 重试或续期不重置告警快照。提醒仍受当前浏览器、租户及用户的弹窗开关、静默时段和重复提醒抑制控制。浏览器后台节流或网络延迟可能增加提醒延迟；快照轮询不补播在两次读取之间已恢复或关闭的告警。升级前已签发的浏览器 MQTT 令牌最长15分钟有效；升级时须撤销旧普通用户的 MQTT 会话或等其过期。

## 存储与租户隔离

权限按当前租户隔离。数据库新增 `platform_access` 表，由已有 PostgreSQL 启动迁移自动创建。每个租户保存独立的用户、角色及递增修订号；写入使用修订号比较，遇到并发更新返回409，需刷新后重试。Redis/ClickHouse包装层透传统一仓储接口，不把账户保存在浏览器或临时文件中。开发用内存仓储提供同样接口，但不跨进程保存。

## 管理接口

| 接口 | 用途 |
|---|---|
| `GET /api/v1/events` | 当前用户授权范围内的活动告警与设备状态；管理员限当前租户 |
| `GET /api/v1/access/device-options` | 当前租户设备授权选项，仅账户管理员可读 |
| `POST /api/v1/auth/login` | 内置管理员或新增用户登录 |
| `GET /api/v1/auth/me` | 当前身份及有效权限 |
| `GET /api/v1/access/permissions` | 可分配菜单、操作目录 |
| `GET/POST /api/v1/access/users` | 用户列表、新增用户 |
| `PUT/DELETE /api/v1/access/users/:id` | 编辑、删除用户 |
| `POST /api/v1/access/users/:id/password` | 重置密码并撤销旧登录 |
| `GET/POST /api/v1/access/roles` | 角色列表、新增角色 |
| `PUT/DELETE /api/v1/access/roles/:id` | 编辑、删除角色 |

配置入口属于管理员权限。受委托的管理用户也必须拥有「用户与权限」菜单及对应管理操作授权；授予用户或角色管理权限意味着允许其分配其他业务权限，应由负责账户管理的人员持有。

## 配置示例

| 授权配置 | 实际效果 |
| --- | --- |
| 设备管理、告警中心菜单 + 指定设备 A | 只读取 A 的设备数据、告警和实时提醒；设备 B 的详情被拒绝 |
| 告警中心菜单 + 指定设备 A，但没有设备管理菜单 | 有效权限移除告警和原始报文菜单，不能读取设备数据 |
| 设备管理菜单 + 无设备范围 | 设备列表为空；可见的运行总览不包含设备统计 |
| 指定主设备 A，未指定其子设备 B | 不自动获得 B；授权子设备时也不自动获得主设备 |
| 当前租户全部设备 + 相应菜单和操作 | 可访问本租户对应业务；仍不能跨租户访问 |

创建用户时先核对只读的所属租户，再分配角色并核对继承范围；仅有例外需要时单独设置设备或附加功能。只有设备管理及全部设备范围还不足以管理账户，仍需「用户与权限」菜单和对应操作。

角色写入接口支持 `deviceScope: none | selected | all` 与 `deviceIds`；用户写入接口另支持 `deviceScope: inherit`。API 调用省略范围时仍默认为 `none`，不会自动扩权。指定设备必须存在且属于当前租户。角色设备字段存于现有 `platform_access.body` JSONB，无须额外表结构迁移。角色范围变更也会更新用户的 `accessVersion`，AI 工具调用重新检查最新范围。

升级已有系统见 [部署升级](DEPLOYMENT.md#用户权限升级)。回归入口为 `go test ./internal/httpapi -run 'Test(RoleDeviceScopeResolution|AssistantUsesCurrentUserPermissionsAndDeviceScope|AccessControlLifecycleAndIsolation|DeviceScopeHTTPIsolation|UserPermissionsCombineRolesAndIndividualGrants|OnboardingFollowsDevicePermissions|DeviceRegistryFiltersBeforePagination)'`；浏览器检查见 [前端说明](../iot_front/README.md)。
