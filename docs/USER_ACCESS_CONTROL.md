# 用户、角色与权限管理

管理员登录后进入「系统维护 → 用户与权限」。先在「角色管理」创建角色并勾选菜单和操作，再在「用户管理」添加用户名、初始密码并分配角色；也可以给单个用户额外授权。用户菜单和操作权限是所有已分配角色与单独授权的并集。新增表单、用户列表明确显示所属租户；用户归属创建者当前登录的租户，登录时填写同一个租户。

每个用户另有「设备访问范围」：无设备、指定设备、当前租户全部设备。新建及历史未配置范围的普通用户默认为无设备；内置管理员仍管理当前租户全部设备。必须同时具有设备管理菜单及设备范围才可读取设备数据；主设备和子设备分别授权，不隐式扩大到关联设备。设备、告警、原始报文、分页总数和总览统计使用同一范围；无权访问的详情、历史、控制和告警处置请求由后端拒绝。

用户名使用3至64位字母、数字、点、横线或下划线；密码至少10字节、最多72字节。密码仅保存 bcrypt 哈希，不提供查询明文密码的接口。需要修改密码时使用「重置密码」。内置环境管理员保留为维护入口，不在此页面编辑或删除。

菜单权限提供对应页面及必要关联数据的读取能力；新增、编辑、删除、发布、下载、设备控制等操作另行授权。勾选操作时同时勾选其所属菜单。界面隐藏没有权限的按钮，后端按实际路由再次校验。一个页面涉及多个接口时，权限列表可能提供多个操作，例如普通问答和流式问答。运行总览只统计授权设备。智能助手、巡检、备份、接入配置、规则、摄像头及用户权限管理属于全租户任务或管理入口，需设备管理菜单、全部设备范围及对应菜单和操作权限；指定设备用户不开放这些全租户入口。受限用户的连接详情只展示自身设备数据，不展示共享接入网关配置及其他设备会话。

修改角色权限后，后续 API 请求立即使用新配置；前端重新进入窗口或刷新后更新菜单和按钮。修改用户、停用用户、重置密码使原登录令牌失效，用户需重新登录。删除后重新创建同名用户不会恢复旧登录。正在使用的角色不能删除；不能删除内置管理员或当前登录账户。普通用户实时消息改为每3秒请求受认证的 `/api/v1/events`，每次按最新设备范围读取告警与状态；不签发浏览器 MQTT 凭据，不能调用 MQTT 压测令牌接口。登录后的初次快照不弹出历史告警，后续新增或更新的活动告警才触发提醒。管理员沿用 MQTT。升级前已签发的浏览器 MQTT 令牌最长15分钟有效；升级时须撤销旧普通用户的 MQTT 会话或等其过期。

权限按当前租户隔离。数据库新增 `platform_access` 表，由已有 PostgreSQL 启动迁移自动创建。每个租户保存独立的用户、角色及递增修订号；写入使用修订号比较，遇到并发更新返回409，需刷新后重试。Redis/ClickHouse包装层透传统一仓储接口，不把账户保存在浏览器或临时文件中。开发用内存仓储提供同样接口，但不跨进程保存。

接口：

| 接口 | 用途 |
|---|---|
| `GET /api/v1/events` | 普通用户授权范围内的活动告警与设备状态 |
| `GET /api/v1/access/device-options` | 当前租户设备授权选项，仅账户管理员可读 |
| `POST /api/v1/auth/login` | 内置管理员或新增用户登录 |
| `GET /api/v1/auth/me` | 当前身份及有效权限 |
| `GET /api/v1/access/permissions` | 可分配菜单、操作目录 |
| `GET/POST /api/v1/access/users` | 用户列表、新增用户 |
| `PUT/DELETE /api/v1/access/users/:id` | 编辑、删除用户 |
| `POST /api/v1/access/users/:id/password` | 重置密码并撤销旧登录 |
| `GET/POST /api/v1/access/roles` | 角色列表、新增角色 |
| `PUT/DELETE /api/v1/access/roles/:id` | 编辑、删除角色 |

配置入口属于管理员权限。受委托的管理用户也必须拥有「用户与权限」菜单及对应管理操作授权；授予用户或角色管理权限意味着允许其分配其他业务权限，应由负责账户管理的人员持有。
