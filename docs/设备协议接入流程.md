# 设备协议接入流程

当前自定义 Go 协议从“设备接入 → Go 源码接入”进入：下载完整模板、编写普通 Go、上传 `.go` 或含 `go.mod` 的项目 ZIP，填写样例并选择产品后，平台自动编译、测试、发布和热切换。第三方依赖随 `vendor` 上传；源码不需要手工编译二进制或编写 manifest。完整步骤见 [Go 源码接入](GO_PROTOCOL_PACKAGES.md)。下文同时保留旧接口契约供已有集成参考。

平台把“协议包”和“产品”分开管理：协议包描述如何把原始载荷解析为标准消息，产品再绑定协议包，设备注册只引用产品。运行时链路为：

```text
设备 / 网关
  -> MQTT、HTTP、TCP/UDP 网关或设备调试接口
  -> RawMessage 原始归档（原文、SHA-256、幂等索引）
  -> iot.raw.message
  -> 产品绑定的协议包 + parser registry
  -> StandardMessage（属性 / 事件 / 状态 / 告警）
  -> 规则、告警、状态、实时推送和 AI 旁路
```

## 选哪一种解析方式

| 设备报文特征 | 协议包解析器 | 是否重新部署 API |
|---|---|---|
| 通用 JSON、路径字段 | `configurable_json_parser` | 否 |
| 固定长度十六进制、校验和和固定偏移 | `configurable_hex_parser` | 否 |
| 需要纯转换但不访问系统能力 | `javascript_sandbox_parser` | 否，受限沙箱 |
| 变长/TLV/复杂报文解析 | `go_protocol_parser` | 否，上传 Go 源码后自动编译；兼容预编译 Worker |
| 已经由平台审核并随版本发布的标准协议 | 例如 `gb26875_dahua_parser` | 需要平台代码发布 |

接入顺序是：

1. 在协议开发中新建协议包，填写协议标识、传输方式、载荷格式和解析器。
2. 用样本报文运行解析调试，确认 `StandardMessage` 的字段、消息类型和时间戳。
3. 对 Go Worker 先上传 artifact；平台保存 SHA-256 和相对路径，不能提交绝对路径。
4. 发布协议包，再在产品管理中绑定协议包。
5. 创建设备或让网关按协议注册设备；真实上报后在原始报文详情查看原文和标准解析结果。

协议包状态为 `DRAFT` 时不会参与生产解析，`PUBLISHED` 才会被产品运行时使用；停用协议包会保留原始证据，但不会继续解析新报文。设备接入指南是设备凭证、MQTT/HTTP 地址和样本联调说明，不等同于协议解析器。

复杂 Go Worker 的输入输出契约和安全边界见 [Go 协议包接入](GO_PROTOCOL_PACKAGES.md)；大华 v1.03 的注册、上报确认和时钟同步请求/应答见 [GB26875 对接说明](GB26875_DAHUA_V103.md)。
