# 设备协议接入流程

新接入分为配置协议和 Go 协议包两条路径。平台只内置通用 JSON、路径映射、固定长度 HEX、校验和与固定偏移字段；包括 GB26875 在内的专用协议通过上传 Go 源码包实现，不再随平台版本增加解析器。

| 设备报文特征 | 接入方式 | 协议更新是否部署平台 |
|---|---|---|
| 已符合标准消息的 JSON | `custom_json_parser` | 否 |
| JSON 路径及字段映射 | `configurable_json_parser` | 否 |
| 固定长度 HEX、校验和、固定偏移 | `configurable_hex_parser` | 否 |
| 变长、TLV、多信息体、厂商或标准专用协议 | Go 源码包，`go-json-lines-v1` 负责解析 | 否 |
| TCP/UDP 分帧、设备识别、会话状态、应答及下行编码 | Go 源码包，`go-protocol-v2` | 否，使用已有监听端口 |

## 从外部协议仓库接入

1. 在你自己的仓库维护独立 Go module。项目 ZIP 根目录放 `go.mod`、源码、`protocol.json`、`samples/cases.json`；完整接入包另放 `samples/operations.json`。第三方依赖先 `go mod vendor` 后随包上传。
2. 在“设备接入 → Go 源码接入”填写协议标识并上传 ZIP。名称、版本、网络、入口、能力和样例留空时读取包内文件。平台编译并运行样例，全部通过后才保存版本。
3. 上传时选择产品并发布，或在“协议与版本”把产品绑定到已发布版本。发布后的版本不可覆盖；修改代码使用新版本号。
4. MQTT/HTTP 使用现有设备上报入口。TCP/UDP 在“TCP / UDP 接入”创建监听实例，选择产品及其绑定版本、监听 IP 和端口。默认只允许已登记设备；可按需要开启自动登记。
5. 设备连接后，到原始报文中检查归档原文和标准解析结果。在“设备接入实例”查看监听状态，在“TCP / UDP 接入”发送协议包支持的命令。
6. 更新时上传新版本并切换产品绑定；回退使用“回滚产品至上一版本”。可随时下载每版原始源码及编译制品，放回外部仓库管理。

```text
TCP/UDP 设备 → 通用监听器 → Go ingress（完整帧、设备 ID、应答、状态）
  → 原始消息归档及事件投递 → Go decode → 标准消息、规则、告警
  → 成功接收后向设备发送 ingress 返回的应答
平台命令 → Go encode → 当前设备连接 → ingress 关联命令应答
```

平台负责租户、产品归属、登记权限、连接、归档和版本；协议包只识别设备及解释线上字节。每帧记录协议 ID 和版本，历史回放继续使用原版本。TCP 半帧和未完成命令保留原版本，完成后下一帧使用新绑定；切换版本会清空包内会话状态，协议应能从后续上报重建状态。下行命令在新版本收到设备上报后执行。

完整说明见 [Go 协议包契约](GO_PROTOCOL_PACKAGES.md)，可直接使用的独立包见 [GB26875 大华接入](GB26875_DAHUA_V103.md)。

## 旧设备与部署

`gb26875_dahua_parser`、内置 Modbus、烟感 HEX、JavaScript 解析器保留给已有显式绑定和历史回放。新增和更新专用协议统一上传 Go 包；旧 Modbus 点表导入不再创建内置版本，协议助手只保存映射草稿。已有 Modbus 轮询实例继续运行，不自动迁移。

本次通用接入能力需要部署一次 API 与前端。之后更新协议、绑定或监听实例无需重启。Compose 默认向 API 映射 TCP/UDP 26875；可用 `IOT_PROTOCOL_PORTS=26875-26885` 预留同号端口范围。增加未映射的容器端口仍需更新部署或网络配置。通用运行时目前提供被动 TCP/UDP 监听和在线会话下行，不提供通用主动拨号、定时轮询或连接生命周期回调。
