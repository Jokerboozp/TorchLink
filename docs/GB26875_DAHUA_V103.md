# GB26875 大华 v1.03：独立 Go 协议包

源码位于 [`protocol-packages/gb26875-dahua`](../protocol-packages/gb26875-dahua)，有独立 `go.mod`，只依赖标准库，不引用平台 `internal` 包。可以单独放进你的协议仓库维护、测试和发版。平台通过 `go-protocol-v2` 调用包中的 `ingress`、`decode` 和 `encode`；无需专用 GB 网关服务。

## 上传与接入

1. 在协议目录执行 `go test ./...`，将根目录内容打成 ZIP：ZIP 内直接包含 `go.mod`、`protocol.json`、源码及 `samples`，不要再套一层目录。
2. 先在平台创建产品。在“设备接入 → Go 源码接入”填 `gb26875-dahua` 并选 ZIP、绑定产品，其余元数据和样例留空读取包内文件，点击上传发布。
3. 在“TCP / UDP 接入”建实例：产品与第 2 步一致、版本 `1.0.0`、IP `0.0.0.0`、端口 `26875`。TCP 与 UDP 分别创建实例，可使用同一端口号。需要从设备源地址自动登记时开启 autoRegister。
4. 将终端目标配置为平台主机地址与该端口。容器部署默认已映射 API 的 TCP/UDP 26875。

首次安装这次通用接入能力需要更新 API 和前端。今后修改本包的版本号、上传并切换产品绑定即可生效；不重建 API 镜像。旧 `gb26875_dahua_parser` 仅为历史绑定和回放保留。

## 报文和命令

包校验 `@@` / `##`、应用数据长度（最多 512 字节）和 8 位累加校验和。支持注册、保活、确认、时钟同步请求/应答及部件状态上报。字段沿用 `fireAlarm`、`fault`、`componentType`、`componentTypeName`、`circuitAddress`、`nodeAddress`、`statusWord`、`objects`；火警/故障产生 `ALARM_REPORT`，正常状态产生 `STATE_CHANGE`。

设备 ID 为 `gb26875_<6 字节源地址的小写十六进制>`。普通上报在平台成功接收原始帧后返回同流水号的 `0x03` ACK；校时请求返回 `0x01` / `0x5A` 校时帧；ACK 不再触发应答。设备无时区的 BCD 时间统一按 UTC+08:00 解释，使 Windows 与 Linux 结果一致。

平台主动校时使用通用接口或页面的下行命令：

```http
POST /api/v2/device-access-profiles/dahua-tcp/devices/gb26875_123456789012/commands
Content-Type: application/json
Authorization: Bearer <operator-token>

{"type":"time-sync"}
```

可选 `timestamp` 是 Unix 毫秒；默认当前时间。终端必须在线，平台按流水号等待确认。其他参数设置/查询命令需在这个独立包内扩展 encode 与对应样例，再上传新版本。

## 独立模拟器

在协议包目录执行（无需平台管理员密码）：

```powershell
go test ./...
go run ./cmd/simulator --address 127.0.0.1:26875 --network tcp
go run ./cmd/simulator --address 127.0.0.1:26875 --network udp
go run ./cmd/simulator --address 127.0.0.1:26875 --hold 1m
```

模拟器发送注册和手报火警并检查 ACK；`--hold` 保持在线，可从页面发送校时命令观察确认。模拟器可能产生测试告警，请使用测试产品。它不创建协议、不覆盖产品绑定。

本机自动化已覆盖真实源码上传、样例执行、TCP 半帧/粘包、UDP、归档和标准消息、主动校时确认、同一连接热切换、失败版本不生效及回滚。现场终端和生产网络仍需实际联调。

### 部件级告警更新

当前独立源码包新增 `event.components`，分别输出每个部件的火警和故障状态。多部件报文顶层不再携带第一部件的地址，完整地址和状态保留于 `objects`，实际告警定位使用对应部件。现有不可变版本需要另行发布新版本并切换绑定；状态时间、恢复和存量告警边界见 [部件告警与 MQTT 持久接收](DEVICE_RECEIVE_RELIABILITY.md)。
