# 边缘功能移除说明

2026-09-10，按用户确认的范围将平台收敛到中心直接接入。此文描述本次源码变更；本轮未重启现有 API 或修改业务数据库。

## 当前能力

保留 MQTT/HTTP 标准设备接入、中心 Modbus TCP 点表采集、Go TCP/UDP 协议监听、GB26875 独立协议、协议源码发布与回滚、原始归档、部件告警及恢复、设备命令、独立 Access Gateway 和执行租约。摄像头保留人工维护元数据、设备关联与外部视频事件接入。

移除节点登记、凭据、心跳、现场任务、现场 Go Worker 分发、节点命令队列、Agent 程序升级与启动器；移除依赖它们的 RTU/OPC UA/SNMP/BACnet 接入入口、ONVIF 现场发现和读取、节点视频目录导入及依赖同一节点接口的独立 `gb28181-metadata` 节点程序。相关 HTTP 路由不再注册，返回 404。可信目录仅接收协议源码条目，不再接受 `kind=edge-agent`。

Go 协议多平台编译仍保留。发布端必须实际通过样例，其余平台只报告编译/未验证状态；不再提供节点下载与现场试跑功能。旧 RTU 与通用轮询响应解析器保留用于历史报文解析和回放，不代表当前仍具备这些协议的现场采集能力。

## MQTT 持久接收不受移除影响

原队列提取为 `internal/durablequeue`，MQTT 引用公共包。磁盘格式、文件名、锁、原子写入、首次接收时间、ACK 前落盘、容量、重试及隔离机制保持兼容。现有 `data/mqtt-inbox/<process-role>/` 和 `client-id` 原地复用，不搬迁、不清空。

## 旧数据与配置

新数据库不再创建 `edge_node`、`edge_read_job`、`edge_program` 或现场命令索引。启动迁移不 DROP 旧表，不删除已有节点、告警、报文、产品或协议制品。旧表成为历史数据，不再由当前 API 管理。

`DeviceAccessProfile.edgeNodeId` 只作为历史配置识别字段保留。非空的旧配置仍禁止中心采集、监听、自动注册和下行；界面报告不支持，新增或保存此类配置返回错误。不会将现场地址静默改为中心地址。需要改成中心接入时，须确认网络及产品协议，重新配置中心实例；RTU 等旧现场任务不能仅清空节点标识后继续运行。

原有运行目录和外部现场程序不会随源码删除被自动清理。存在其他现场部署时须由部署者停止对应 Agent，并保留必要历史数据；本轮核实的本地部署没有登记节点和接入实例。

## 验证

实际命令、结果和未执行范围统一记录在 [实施进度](DEVICE_ACCESS_REFACTOR_PROGRESS.md) 的“移除边缘节点与现场 Agent”章节。数据库迁移、MQTT 持久性、中心接入、协议发布和前端交互分别验证，不将编译通过当作真实设备验收。

后续中心接入扩展增加 TCP 主动连接、查询调度与 RTU over TCP 网络透传，未恢复串口驱动或现场 Agent。主子设备属于业务台账关系，使用原有 `gatewayId` 字段，与已移除的边缘节点无关。参见 [TCP 主子设备接入](TCP_CHILD_DEVICE_ACCESS.md)。
