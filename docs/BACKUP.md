# 备份与隔离恢复

[操作与权限](#操作与权限) · [备份范围](#备份范围) · [制品与版本](#制品与版本) · [恢复验证](#恢复验证) · [恢复后的使用边界](#恢复后的使用边界)

服务启动、自动备份时间和恢复目标配置见 [部署指南](DEPLOYMENT.md#设备数据备份)，测试入口见 [AI 与知识库回归](DEVELOPMENT.md#ai-与知识库回归)及[业务分析与治理回归](DEVELOPMENT.md#业务分析与治理回归)。备份服务保护全平台范围的设备消息及下列扩展资料，操作入口为“备份管理”。

## 操作与权限

平台管理员或 `IOT_OPS_TENANTS` 中获得对应菜单和操作权限的用户才能访问全平台备份。普通租户的全部设备范围不构成备份授权。浏览器只调用平台 API，备份服务地址、管理员令牌及数据库凭据保留在服务端。

| 操作 | 行为与接口 |
| --- | --- |
| 查看记录 | `GET /api/v1/backups`，按类型、状态筛选并分页；详情展示本次结果和文件 |
| 立即备份设备数据 | `POST /api/v1/backups`，类型 `FULL`，导出当前保留的数据及以下扩展组件 |
| 备份昨日数据 | 同一接口，类型 `DEVICE_DAILY`，按配置时区导出前一个自然日的设备数据 |
| 下载文件 | `GET /api/v1/backups/{id}/files/{filename}`，下载清单及各制品，响应附 SHA-256 |
| 文件校验 | `POST /api/v1/backups/{id}/restore-drill`，检查制品能否读取和摘要是否一致 |
| 恢复验证 | `POST /api/v1/backups/{id}/restore`，恢复到服务端指定的独立数据库、对象桶与目录 |
| 删除备份 | `DELETE /api/v1/backups/{id}`，删除制品和记录；运行中任务或仍被文件校验记录引用的备份返回 409，清理失败保留记录供重试 |

每日自动备份默认开启，每天上海时间 00:05 执行昨日备份；服务停机期间不会自动补跑。关闭自动备份仍可手动执行。单个备份服务实例内，备份、恢复、文件校验和删除互斥执行；该锁不提供跨副本协调。旧接口类型 `RAW_LOGS`、`INCREMENTAL` 映射为昨日设备数据备份。

## 备份范围

| 组件 | 每日设备备份 | 当前 FULL |
| --- | --- | --- |
| 设备消息 | PostgreSQL、ClickHouse 的原文与解析数据，按日期导出 | 当前保留的设备消息及读取来源 |
| 知识库 | 不包含 | 四张知识表、分片和向量、Agent 绑定、索引版本及引用的 MinIO 原件 |
| Harness | 不包含 | 所有已配置实例的动态 Agent 与会话快照 |
| 值班 | 不包含 | 排班、实际班次、记录、交接版本、跟进事项、通知、事件台账及附件原件 |
| 五项业务分析 | 不包含 | 配置、固定任务/快照/证据、人工核实、AI 版本、业务记录、规则历史/trace、权限关联及私有附件 |
| 反复报警治理 | 不包含 | 逐次观测、配置/事项/轮次及历史、现场记录/活动、原因措施、观察/报告、来源版本、待办及私有附件 |
| 用户与权限 | 不包含 | `platform_access` 权限快照，包含账号、角色、设备范围及开放接口密钥摘要 |

FULL 不包含 Provider / Embedding API Key、JWT 或服务令牌、Redis、消息队列、环境文件或整个 MinIO。开放接口密钥明文仅创建时返回，不能从摘要恢复。业务备份不是整台主机或全部配置的镜像；环境凭据需另行保管。

设备原文按接收时间分日，PostgreSQL 标准消息按处理时间分日（旧记录回退到消息时间），ClickHouse 遥测按消息时间分日。两种存储分别保留来源，可能含同一消息的不同表示。

## 制品与版本

制品保存在配置的 MinIO 备份桶，默认 `iot-backups`。清单记录组件、来源范围、数量、大小和 SHA-256；以清单识别范围，不能把缺失文件当作“本版本未包含”。

| 格式 | 在前一基础上增加的内容 | 含清单的文件数 |
| --- | --- | --- |
| 历史 v1 / 当前每日（v2 设备数据） | 原始数据、解析数据 gzip JSONL 和清单 | 3 |
| FULL v2 | 知识结构/数据/原件和 Harness 快照 | 7 |
| FULL v3 | `duty-schema.json`、`duty-postgres.jsonl.gz`、`duty-objects.tar.gz` | 10 |
| 原五应用 v4 / 原治理 v4 | 对应专题的结构、数据、附件；两种 v4 依清单区分 | 13 |
| 当前 FULL v5 | 同时包含 `application-*` 与 `governance-*` 两组三文件 | 16 |

当前 PostgreSQL 扩展资料在同一个 repeatable-read 截止中导出。五项应用与治理共用的 `analysis_document` 只导出一次，属于 application 组件；ClickHouse 来源覆盖单独记录。

## 恢复验证

恢复目标由备份服务配置，浏览器不能指定任意数据库。未配置 PostgreSQL 恢复目标或目标与源业务库身份相同，备份服务返回 412；平台转发接口将这类上游拒绝显示为 502 并保留具体原因。恢复前核对源/目标身份，数据库地址别名也不能绕过同库检查。

| 组件 | 隔离恢复位置与核对 |
| --- | --- |
| 设备消息 | 目标库 `restored_message`、`restore_run`，按清单核对条数和消息数 |
| 知识库 | `kb_restore_<标识>` schema；恢复 pgvector 索引、绑定及引用，原件在恢复 MinIO 的独立前缀 |
| Harness | 恢复到独立目录，核对每实例快照数量和内容，不写活跃 Harness 卷 |
| 值班 | `duty_restore_<标识>` schema；附件在 `iot-duty-attachments` 恢复前缀；重定位附件不重签原交接 |
| 应用分析 | `application_restore_<标识>` schema；核对正文哈希、版本/当前指针、任务/快照、实际发送 AI 的引用、规则历史及权限继承 |
| 治理 | `governance_restore_<标识>` schema；核对专用表、历史、来源任务、事项/轮次、观察计划及报告；附件在治理私有桶恢复前缀 |

恢复只使用编译内置 DDL，制品中的 schema 用于核对，不执行其中 SQL。生成列、外键、索引、序列和不可变版本均须核验。附件核对 SHA-256 与字节数；应用附件以只读位置映射保留原引用/配置哈希，治理当前及历史存储键重写到恢复前缀。旧校准附件没有上传时哈希的情况标记为原始哈希未知，只能核对本次制品摘要。

旧 v1/v2/v3 及每日备份将未包含的专题标为 `not_included`。原五应用 v4 不含治理，原治理 v4 不含五应用；治理 v4 的分析文档在治理 schema 中恢复。恢复保留旧正文哈希，JSONB 数字表达变化仅允许数学值精确相等且匹配原 SHA 的有界还原，不重写原摘要。

## 恢复后的使用边界

文件校验成功、隔离恢复成功和全部原始来源可以再次查询是三个独立结论。恢复只提供备份时仍保留的 PostgreSQL 来源；ClickHouse 制品暂存核对，不重建可查询冷库。旧 MinIO 原文或已过期来源缺失时，固定报告保留原事实并显示覆盖限制；这些来源限制使结果为 `PARTIAL`，不等同于数量不一致。

恢复库供只读历史核对。事实 / AI / 交接任务保留原审计后退役，旧租约和规则 pending 不能接续，不自动调用模型、处理消息或执行生产动作。治理上传尝试统一标为 `UPLOAD_RESTORED`；正式引用映射到恢复前缀，未提交对象不恢复，只保留原键 hash，恢复副本不继续源环境上传补偿。

新功能启用时先更新 API 完成迁移，再更新前端与 Harness，最后更新备份服务。恢复结果应记录具体版本、目标、成功组件及限制；本文不是目标环境恢复验收记录。源码入口为 `internal/backup/` 与 `internal/httpapi/backups.go`。
