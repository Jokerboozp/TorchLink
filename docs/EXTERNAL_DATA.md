# 外部数据接入

外部数据接入管理 HTTP/HTTPS + JSON 接口，支持第三方主动推送、定时拉取、手动拉取与历史补拉。同一个外部系统的多个接口共用编号对应关系和事件身份，因此推送与拉取可以同时使用。厂商私有加密协议、XML、非 HTTP 接口需要额外编写适配器，不属于表单可直接解释的格式。

源码入口为 `internal/externaldata/`、`internal/httpapi/external_data.go`、`internal/core/external_data.go` 和 `iot_front/src/views/ExternalDataView.vue`。视频平台告警统一经此模块接入（推送或拉取），平台不再提供单独的视频告警 Webhook 或 MQTT 视频告警主题；使用平台固定格式的调用方使用[开放接口](INTEGRATION.md#开放接口)。

## 配置步骤

1. 在“外部数据接入 → 接入配置”登记来源和执行用户。拉取及媒体证据下载需要精确的允许主机与端口，例如 `video.example.internal:443` 或 `192.168.10.20:8080`。平台发起的请求默认只能到达公网地址：允许主机解析到内网、回环或运营商级 NAT 地址时，须把对应网段加入 `IOT_EXTERNAL_DATA_ALLOWED_CIDRS`（逗号分隔 CIDR）；云元数据、链路本地与组播地址任何情况下都不可访问。校验发生在实际连接的地址上，域名解析后被改指向内网也会被拒绝，并忽略 `HTTP_PROXY` 等代理环境变量。
2. 展开来源，点击“新增接口”添加推送或拉取接口，选择数据用途。默认保持草稿，配置认证、字段转换和分页后，用“样例测试”检查转换结果；拉取接口也可“请求预览”。这两项测试不生成正式告警。
3. 在“编号对应”关联外部编号与现有平台设备或摄像头；也可在“运行记录”中对“等待编号绑定”的接收记录点击“关联并重试”，平台按记录的来源和对象编号预填，保存后自动重新处理该记录。摄像头必须启用且关联一个平台设备，后者决定告警访问范围；不会自动创建设备、摄像头或登录账户。
4. 启用外部系统和接口。推送接口的“接收设置”显示完整回调地址及认证说明；默认接收密钥仅生成/轮换时显示一次，将其保存到对方服务端。
5. 在“运行记录”切换查看接收记录与拉取任务：原文、转换结果、配置修订及对应告警。未知编号保留为“待关联”；字段错误可修改配置后按当前规则重新处理。

推送要求对方配置回调，且对方服务器能访问平台地址。拉取由 Jobs 职责的进程执行，不依赖浏览器保持打开。管理端/API/Parser/Processor/Jobs 升级时使用同一版本。

## 接口与认证

公共推送地址为 `POST /api/external/v1/{tenantId}/{endpointId}`，租户和执行用户从已保存配置确定，正文不提供改写权限的入口。默认认证为 `X-API-Key: <接收密钥>` 或 `Authorization: Bearer <接收密钥>`。无配置、停用、权限失效和认证失败均不会返回业务成功。

来源认证供接口继承，单个接口可覆盖：

| 方式 | 约定 |
| --- | --- |
| 默认接收密钥 | 推送端专用；后台仅保存摘要，轮换后旧密钥立即失效 |
| Bearer | `Authorization: Bearer <secret>` |
| API Key | 自定义请求头或查询参数，二选一 |
| Basic | 用户名及密码 |
| HMAC | 默认 `X-Timestamp`（Unix 秒）和 `X-Signature`；签名为 `hex(HMAC-SHA256(secret, timestamp + rawBody))`，不插入分隔符；接收容许五分钟偏差 |
| 登录获取 Token | 仅主动拉取；配置登录 URL、JSON 正文、Token 字段路径和有效秒数字段路径；缓存令牌，401 时刷新一次 |

Token 请求中的密码/密钥引用 `{{secret}}`，不将明文凭据写进普通请求参数。认证凭据留空表示沿用已保存值，清除需显式勾选。认证 URL、重定向及业务 URL 都受来源允许主机端口约束；携带认证的业务请求不跨来源重定向。

持久凭据使用 AES-GCM 加密，密钥按用途从运行环境的 `IOT_JWT_SECRET` 派生。所有副本必须保持该秘密一致；轮换该秘密前应准备重新录入外部接口凭据。备份不包含环境秘密，不能仅靠数据文件恢复解密能力。

推送最大正文 1 MiB。成功响应状态码和 JSON 正文可配置，默认 `202 {"accepted":true}`。该响应表示原始数据已经持久接收，后续是否生成告警以接收记录为准。接口每秒接收预算为 30 次，沿用现有共享限流；限流时返回 429 与 `Retry-After`。

## 数据提取和转换

支持单条对象或列表，并可配置响应成功条件、列表所在路径、条件过滤、固定值、默认值、类型转换、枚举转换及时间转换。路径支持嵌套字段和数组下标。时间支持秒、毫秒、RFC3339 或 Go 时间格式；无时区字符串可以指定 IANA 时区。

| 目标字段 | 用途 |
| --- | --- |
| `id` | 外部稳定事件编号；没有时用组合字段生成，需验证不会碰撞 |
| `objectId` | 对方的设备/摄像头编号；不直接接受平台对象权限 |
| `timestamp` | 事件发生或更新的毫秒时间；不同于平台接收时间 |
| `version` | 可选整数版本；双方均有版本时优先用于先后判断 |
| `status` | `ACTIVE`、`RECOVERED`、`CLOSED`；外部 CLOSED 按恢复处理，不覆盖人工关闭 |
| `alarmType`、`alarmLevel`、`content` | 告警类型、等级与内容 |
| `confidence` | 视频识别置信度 |
| `snapshotUrl`、`videoClipUrl` | 视频告警证据 |
| `online` | 设备连接状态 |
| `data` / `data.xxx` | 属性、事件等业务字段 |

例如对方的 `eventId`、`cameraCode`、`occurredAt`、`eventType` 分别对应 `id`、`objectId`、`timestamp`、`alarmType`；将类型编码 `fire` 映射为 `FIRE`，状态编码 `resolved` 映射为 `RECOVERED`。

视频和设备告警、属性及状态都经过标准原始报文归档、解析和业务处理，记录保留 `messageId` 与告警关联。属性、状态和普通事件沿用现有规则聚合与恢复；外部告警按事件身份管理生命周期。普通事件没有对象关联时仅保存在外部事件记录中；关联设备的事件进入标准事件链路。无效字段不会伪造成功消息。

## 拉取与断点

请求支持 GET、POST、PUT，以及请求头、查询参数和 JSON 正文。动态参数为 `{{from}}`、`{{to}}`（毫秒）、`{{page}}`、`{{cursor}}`、`{{pageSize}}`。分页支持无分页、页号、偏移量和游标。参数名可配置；正文中使用分页模板且未指定查询参数名时，不额外注入默认查询参数。

自动周期为 10 秒至 30 天，0 表示仅手动。首次起点可指定；未指定时从启用配置时刻开始，不自动扫描全历史。可以配置回看时间窗口以补收晚到事件。手动任务选择独立起止时间，不改变自动进度。

外部系统（来源）配置 `requestIntervalMillis`（最小请求间隔，毫秒）：`0` 使用默认 `1000`，非零取值为 `100` 至 `3600000`，后端也校验此范围。它限制同一租户、同一来源下所有接口的合计请求频率，与自动任务执行周期不同，分页中的每次请求也受限制。

自动拉取、手动补拉、请求预览以及登录获取/刷新 Token 共享持久节流状态，多个副本和进程重启不会清空窗口。后台任务遇到节流会保存下一执行时间，不增加失败尝试次数，也不推进页号、游标或自动水位。请求预览可短暂等待最多 2 秒以完成同一窗口后的下一请求；较长等待由页面显示限流响应。

对方返回 `429` 时，平台解析 `Retry-After` 的秒数或 HTTP 日期，将整个来源延后；等待范围为 1 秒至 24 小时，缺少或无法解析时默认 60 秒。业务接口的失败原文仍保留，登录 Token 接口的响应不会写入业务接收记录。冷却期间其他接口和手动任务同样等待，不能通过另起任务或重启进程绕过。

每页原文及接收记录可靠保存后才推进页号或游标；整个时间窗口完成后才推进自动水位。最大页数用于中止异常分页，达到限制且仍有下一页时明确失败。配置变更不会拿旧游标解释新接口：旧任务保留为失败，新自动任务从未推进的水位按新配置重新开始。

任务进度展示实际页数与收到数量，并分别统计已处理、待处理和失败记录。“拉取完成”不代表其中每条业务记录均处理成功。网络失败采用退避重试，超过尝试次数后可人工重试；任务、原文和配置修订均持久保存。

## 去重、状态和媒体证据

事件身份为“租户 + 外部系统 + 数据用途 + 外部事件编号”，不使用接口编号，因此推送与拉取共享同一身份。同一事件不能切换关联设备或摄像头，新的对象应使用新的事件编号。相同内容重复到达不产生新告警；旧版本或旧时间忽略；同一版本/时间内容不同标记冲突。

同一外部事件的每次投递串行完成。原文已入队但尚未处理时，后到恢复消息等待前一版本，避免先恢复再生成孤立告警。失败保存上一成功版本和未完成投递状态，重启后继续。接收、队列、业务结果分开记录；后台多个实例通过数据库租约领取任务，旧租约不能提交覆盖新工作。

匹配现有规则时保留规则处理及联动动作；未匹配规则的告警也会保留。每个外部事件持有独立告警生命周期，同设备同类型的不同外部事件不共用可被相互恢复的告警。若事件更新造成告警分类变化，保留其全部历史告警关联，恢复时处理该事件仍活动的关联告警。人工关闭和已恢复状态不会被重复活动消息重新打开；新一轮独立事件应使用新事件编号。

截图和片段分别后台归档，失败保留原地址与原因，支持退避和人工重新排队。媒体失败不阻塞文字告警。来源的允许主机端口同样约束下载及重定向。告警详情按具体事件显示状态与已归档证据，下载仍检查告警权限和关联设备范围，不接受任意对象地址参数。

## 权限、持久化和接口

管理菜单键为 `externalData`，新增、编辑、删除、测试、拉取、接收、轮换密钥和重试分别使用精确操作权限。配置与未关联原文属于租户级数据，管理页面要求全部设备范围；执行用户可以仅有选定设备范围。普通管理用户只能配置绑定自己的来源；平台管理员可绑定其他执行用户。

执行用户须启用，具备外部接入菜单和对应接收或拉取权限，设备业务另需设备菜单。每次接收、拉取和业务投递重新读取其当前授权；恢复告警还需告警菜单及处置权限。摄像头关联设备是视频告警的设备范围依据。

管理基础路径为 `/api/v1/external-data`：

| 资源/操作 | 路径 |
| --- | --- |
| 来源、接口、编号对应 CRUD | `/sources`、`/endpoints`、`/bindings`，编辑/删除追加 `/:id` |
| 接收记录、详情、重试 | `/records`、`/records/:id`、`/records/:id/retry` |
| 拉取任务、重试 | `/jobs`、`/jobs/:id/retry` |
| 手动拉取 | `/endpoints/:id/pull` |
| 样例/请求预览 | `/endpoints/:id/test`、`/endpoints/:id/test-fetch` |
| 接收密钥轮换 | `/endpoints/:id/rotate-key` |
| 受登录身份授权的接收 | `/endpoints/:id/receive` |
| 告警证据读取/重新排队 | `/api/v1/alarms/:id/media/:kind`、`/api/v1/alarms/:id/media/retry` |

列表使用 `page` / `pageSize`，支持来源、接口及状态筛选。新建 `revision=0`，编辑和重试需当前修订；删除通过查询参数 `revision` 提交。已被任务或接收历史引用的来源/接口保留，使用停用控制运行。

PostgreSQL 启动迁移创建 `external_data_entry`，保存配置、编号对应、原始接收、事件状态、任务与进度；生产运行使用该持久存储。memory 适配器用于单元和浏览器隔离测试，进程退出不保留数据。

本模块配置、密文凭据、记录与任务纳入 `FULL` 备份，恢复验证使用隔离 schema；完整范围及环境秘密要求见[设备数据备份](DEPLOYMENT.md#设备数据备份)。

## 回归入口与验收边界

源码回归、PostgreSQL 与备份联调、浏览器夹具统一见[外部数据接入回归](DEVELOPMENT.md#外部数据接入回归)。

模拟平台、数据库契约和浏览器验收不能代替厂商现场验收。接入实际视频平台时，还应使用其真实请求、签名、分页及恢复样例验证网络可达性、截图/片段授权和事件编号稳定性。
